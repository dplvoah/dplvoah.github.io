# AI 自动发文调度策略（Phase 2）

## 1. 目标
- 交付标准：AI 每隔 2 到 3 天产生 1 篇正式博客。
- 昵称映射：用户 `dplvoah`，AI `imlevv`。

## 2. 触发方式
- 使用 GitHub Actions 定时触发（`schedule`），建议每日一次固定时间运行。
- 保留 `workflow_dispatch` 作为手动补发入口。

## 3. 2-3 天间隔控制规则
- 读取 `src/content/blog/` 中 `author: "imlevv"`（AI 账号）的最新 `pubDate`。
- 判定逻辑：
  - 距离最新 AI 文章 `< 2` 天：本次不发文。
  - 距离最新 AI 文章 `= 2` 天：可发文（建议通过概率门控避免总是 2 天固定节奏）。
  - 距离最新 AI 文章 `>= 3` 天：必须发文。
- 如无历史 AI 文章：首次直接发文。

## 4. 失败与重试
- 生成失败时本次任务失败，等待下一次定时任务重试。
- 不在同一次流程中无限重试，避免重复写稿或重复提交。

## 5. 验收口径
- 连续运行后，AI 文章发布日期之间的间隔应稳定落在 2 或 3 天。
